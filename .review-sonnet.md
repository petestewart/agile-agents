# T200 review (sonnet)

Diff: `origin/claude/phase-7...T200-project-record`

## BLOCKING

1. **`agile project new --repo` does not support repeated flags, breaking the Phase 7 QA script.**
   - `packages/cli/src/commands/project.ts` implements `--repo` as a single, comma-separated
     option (`repoList()` splits on `,`), used by both `runProjectNew` and `runProjectSet`.
   - `packages/cli/src/args.ts`'s `parseArgs` stores options in a plain
     `Record<string, string | true>` keyed by flag name — a second `--repo <value>` simply
     **overwrites** the first (`options[key] = next` each time `--repo` is seen). There is no
     array accumulation anywhere in the parser.
   - PLAN.md's Phase 7 QA script (line 867) calls:
     `agile project new --name Shop --repo ledger-lite --repo agile-test-repo --json`
     i.e. repeated `--repo` flags, not a comma-separated list. With the current parser and
     `repoList()`, this call ends up with `options.repo === 'agile-test-repo'` only —
     `ledger-lite` is silently dropped, and the created project ends up with `repos:
     ['agile-test-repo']` instead of both repos. This is not a cosmetic gap: `ledger-lite` is
     used later in the same QA script (e.g. lines 1035, 1280) under project `$SHOP`, so the
     project's repo list is wrong for the rest of the script.
   - The CLI's own doc comment even says `--repo` takes "a comma-separated list … like `repo add
     --protected`", but the ticket/PLAN usage is space-separated repeats. This needs an actual
     fix to the arg parser (accumulate repeated `--repo` into an array) or at minimum a
     `--repo`-specific repeated-flag reader, updated in both `runProjectNew` and `runProjectSet`.
   - Confirmed this is unexercised by tests: `packages/cli/src/project.e2e.test.ts` only ever
     passes a single `--repo shop-web`, so the repeated-flag path is not covered and the bug
     passes CI as-is.
