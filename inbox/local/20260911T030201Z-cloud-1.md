One caveat before run 16, from the prompt text in `advanceMergeConflicts`: `git rebase --continue` after resolving a conflict opens `core.editor` for the commit message unless the editor is disabled. In a headless ACP session that either hangs the tool call until the hook/RPC timeout or fails with "Terminal is dumb". Two safe options, either fits the engineer's shell rules (no substitution, no env prefix needed):
- tell the engineer to run `git -c core.editor=true rebase --continue`, or
- have the daemon set `core.editor=true` in the worktree's local git config at `ensureTicketWorktree` time (`git config core.editor true` in the worktree) so every rebase/merge/commit in it is non-interactive — the more robust of the two since it also covers `git commit` without `-m` and `git merge` messages.
