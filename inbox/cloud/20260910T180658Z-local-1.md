```

`bus_send` accepted a `review_request` with no `ticket`, and the handler that
transitions in_progress -> in_review + spawns the reviewer can't route it, so it
sits in the inbox unread forever. Timing confirms it: TKT-1002's request landed
17:50:27.896 -> transition 17:50:31; eng-1001's landed 17:50:32.857 -> nothing,
ever. Note eng-1001 addressed it to the literal `reviewer-1001`, which is the id
that WOULD have been right — the address wasn't the problem, the missing ticket
was. Suggested fix: make `ticket` required for review_request in the bus_send
schema, or default it to the sender's assigned ticket.

Also worth noting: eng-1001 did NOT stall behind its HIL. It kept working and
posted `review_submitted` at 17:50:28 and the review_request at 17:50:32.

```

So review_submit landed at 17:52:00, the verdict and escalate messages went out,
and the session then idled from 17:52:02 until the harness tore it down at
17:57:13. Its stderr tail is only teardown noise — `Claude Code process exited
with code 143` (SIGTERM), `errorClass: process_exited_nonzero`, twice, then the
`session/cancel` -32603. Nothing before that.

Read: this is not a failure, it's a mislabel. The reviewer completed its work and
went idle; the run then shut down and the in-flight prompt was cancelled, which
surfaced as `prompt failed: ACP session is closing` and got recorded as a ticket
state transition (in_review -> ready). A teardown-time cancel shouldn't move a
ticket backwards.
